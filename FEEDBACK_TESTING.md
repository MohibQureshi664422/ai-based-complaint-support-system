# Acceptance and feedback worksheet
Use fresh accounts or anonymized test data. Do not invent participant responses.

| Task | Expected | Actual / pass / fail |
|---|---|---|
| Register and login | New user has only own complaints | |
| Submit technical/billing examples | Appropriate category/routing, ID | |
| Upload PDF/PNG/JPEG | Private downloadable evidence | |
| Invalid file / >5 MB | Rejected | |
| Different customer downloads evidence | Rejected | |
| Edit unassigned Submitted complaint | Details, analysis and history updated | |
| Delete and Cancel | Cancel preserves; confirm archives | |
| Admin assignment | Matching department staff receives complaint | |
| Staff reply and resolve | Customer sees response/status/notification | |
| Department/category update | New complaints use revised route | |
| FAQ supported/unsupported questions | Answer or fallback, no invented policy | |
| CSV | Active records exported | |
| Mobile width | Navigation and forms usable; table scrolls | |

Ask each consenting test participant to rate 1–5: navigation ease, submission ease, tracking clarity, response clarity, overall satisfaction. Record anonymized participant IDs, task durations, errors and comments. Report actual sample size and mean ratings; do not imply statistical certainty from a few participants.

Resolution efficiency: record submitted and resolved timestamps in test cases and compute durations. Compare against an observed baseline only if one was measured. Model latency in evaluation JSON is inference latency, not real organizational resolution time.
